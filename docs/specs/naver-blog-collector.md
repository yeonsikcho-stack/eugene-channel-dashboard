# Spec — naver-blog-collector

## Status: 보류

실제로 로그인 자동화를 테스트해본 결과, 네이버가 이 환경을 "새로운 곳에서의 로그인"으로 인식해 사람만 풀 수 있는 보안 확인(캡차)을 요구했다. 반복 시도는 계정 잠금 위험이 있어 중단했다. 담당자와 상의한 결과, 지금은 자동 수집을 시도하지 않고 **manual-metrics-entry로 네이버 블로그 지표를 계속 수동 입력**하기로 결정했다 (2026-10-10). 아래 내용은 추후 "본인이 직접 로그인해서 세션만 재사용하는 방식" 등으로 재시도할 때 참고용으로 남겨둔다.

## Problem Statement

담당자가 매달 네이버 블로그 관리자 페이지에 로그인해서 조회수·방문자수를 확인하고 엑셀에 옮겨 적는다. 네이버 블로그는 공식 통계 API를 제공하지 않아, 유튜브처럼 API 키로 간단히 가져올 방법이 없다 — 관리자만 볼 수 있는 통계 화면에 직접 로그인해서 눈으로 읽는 것이 유일한 방법이다.

## Solution

저장된 네이버 로그인 정보로 블로그 관리자 통계 화면에 자동으로 접속해, 조회수·방문자수를 가져와 metrics-store에 채워 넣는다.

- 담당자의 네이버 계정 ID·비밀번호를 설정 값으로 저장해두고, 헤드리스 브라우저로 로그인해 통계 화면의 숫자를 읽어온다.
- 네이버는 공식 API가 없는 비공식 경로이기 때문에, 캡차·새 기기 인증·화면 구조 변경 등으로 **언제든 멈출 수 있다는 것을 전제**로 만든다. 멈추면 담당자가 화면에서 바로 알 수 있고, manual-metrics-entry로 그 달 숫자를 직접 채울 수 있다.
- 로그인에 성공하면 그 로그인 상태(세션)를 보관해 재사용한다. 수집할 때마다 매번 새로 로그인하지 않는다 — 매번 로그인을 시도하면 네이버가 "새로운 환경에서의 로그인"으로 더 자주 막을 수 있기 때문이다.
- 담당자는 화면에서 연결 상태(정상/오류)와 마지막 성공 시각을 보고, "지금 수집"을 눌러 즉시 실행해볼 수 있다.

## User Stories

1. As a 담당자, I want 네이버 블로그 조회수·방문자수가 자동으로 채워지길, so that 매달 로그인해서 눈으로 확인하지 않아도 된다.
2. As a 담당자, I want 자동 수집이 로그인 문제로 멈추면 화면에서 바로 알 수 있길, so that 보고서를 준비하다가 갑자기 숫자가 비어서 당황하지 않는다.
3. As a 담당자, I want 자동 수집이 멈췄을 때 왜 멈췄는지(로그인 필요/화면 구조 변경 등) 대략적인 이유를 보고 싶다, so that 내가 할 수 있는 일인지 개발자를 불러야 하는지 판단할 수 있다.
4. As a 담당자, I want 자동 수집이 안 될 때도 manual-metrics-entry로 그 달 숫자를 바로 채울 수 있길, so that 보고서 작성이 막히지 않는다.
5. As a 담당자, I want 수동으로 고친 네이버 블로그 지표 값이 다음 자동 수집에 덮어써지지 않길, so that 어렵게 고친 값이 되돌아가지 않는다.
6. As a 담당자, I want 지금 당장 네이버 블로그 수집을 눌러서 실행해볼 수 있길, so that 정기 수집을 기다리지 않고 바로 숫자를 채울 수 있다.
7. As a 담당자, I want 네이버 로그인 정보(ID·비밀번호)가 코드나 화면에 노출되지 않길, so that 계정이 안전하게 보관된다.
8. As a 개발자, I want 매 수집마다 새로 로그인하지 않고 로그인 상태(세션)를 재사용하길, so that 네이버가 비정상적인 로그인 패턴으로 계정을 더 자주 막지 않는다.
9. As a 담당자, I want 저장된 로그인 세션이 만료되면 자동으로 다시 로그인을 시도하길, so that 매번 내가 직접 재연결하지 않아도 된다.
10. As a 담당자, I want 자동 재로그인도 실패하면(캡차 등으로) 더 이상 반복 시도하지 않길, so that 계정이 의심스러운 활동으로 잠기지 않는다.

## Implementation Decisions

**인증 방식**

- 네이버 로그인 ID·비밀번호를 비밀 설정 값으로 보관한다 (코드에 넣지 않음, 화면에 노출하지 않음).
- 헤드리스 브라우저(예: Playwright)로 네이버 로그인 페이지에 접속해 ID·비밀번호를 입력하고 로그인한다.
- 로그인에 성공하면 인증 쿠키(세션)를 로컬에 저장해 재사용한다. 저장 위치는 git에 올라가지 않는 곳에 둔다 (metrics-store의 SQLite 파일과 같은 위치인 `data/` 디렉터리 등, `.gitignore`로 이미 제외된 경로).
- 수집을 실행할 때: 저장된 세션이 있으면 먼저 그 세션으로 통계 화면 접근을 시도한다. 세션이 없거나 만료되어 로그인 화면으로 튕기면, 저장된 ID·비밀번호로 다시 로그인을 시도하고 성공하면 새 세션을 저장한다.
- 로그인 시도 중 캡차·2단계 인증·새 기기 인증 화면이 나타나면, 자동화로는 통과할 수 없으므로 더 이상 재시도하지 않고 연결 상태를 `error`로 표시한다 (반복 재시도는 계정을 더 의심스럽게 만들 수 있어 금지).

**수집 대상**

- 블로그 관리자 통계 화면에서 그 달의 조회수·방문자수를 읽어온다. 정확한 추출 방법(렌더링된 화면의 텍스트를 읽을지, 통계 화면이 내부적으로 호출하는 API 응답을 가로챌지)은 구현 시점에 네이버 블로그 통계 화면의 실제 동작을 확인하고 결정한다 — 둘 중 더 안정적인 쪽을 쓴다.
- 대상 블로그는 하나(유진그룹 블로그)이며, 블로그 주소(블로그 ID)는 로그인 ID와 같을 수도, 다를 수도 있으므로 별도의 설정 값으로 분리해 보관한다.

**연결 상태 관리**

- 연결 상태를 `connected | disconnected | error`로 관리하고, 마지막 수집 성공 시각과 마지막 오류 메시지(사람이 읽을 수 있는 짧은 설명: "로그인 필요", "캡차 감지됨", "통계 화면 구조가 바뀜" 등)를 함께 보관한다.
- 오류의 구체적인 원인(캡차/2단계 인증/화면 변경/기타)을 구분해서 보여주되, 담당자가 스스로 해결할 수 있는 종류가 아니므로 "다시 연결하기" 같은 담당자 액션은 제공하지 않는다 — youtube-collector의 OAuth 재연결과 다르게, 네이버 쪽은 ID·비밀번호가 바뀌지 않는 한 담당자가 화면에서 직접 복구할 방법이 없다. 오류 발생 시 담당자가 manual-metrics-entry로 그 달 숫자를 직접 채우는 것이 유일한 대응이다.

**화면**

- youtube-collector와 같은 형태의 채널 상세 화면(`/channels/naver_blog`)에 연결 상태, 마지막 성공 시각, 오류 메시지, "지금 수집" 버튼을 둔다.

**metrics-store와의 연결**

- 수집한 값은 `channel: naver_blog`, `metricKey: views | visitors`, `yearMonth`, `source: auto`로 metrics-store에 upsert한다.
- 해당 (채널, 지표, 연월)에 `is_manual_override`가 설정되어 있으면 자동 수집 값을 저장하지 않고 건너뛴다 (metrics-store의 기존 규칙 재사용).

## Out of Scope

- 정기적으로(예: 매일 1회) 자동 실행되는 스케줄링 — collection-scheduler의 범위.
- 캡차·2단계 인증을 우회하거나 자동으로 통과시키는 기능 — 시도하지 않는다. 막히면 멈추고 담당자에게 알린다.
- 네이버 블로그의 조회수·방문자수 외 다른 지표(이웃수, 공감수 등) — PRD에 없는 지표는 다루지 않는다.
- 여러 블로그 동시 관리 — 유진그룹의 단일 블로그만 대상으로 한다.
- 콘텐츠(게시물) 단위 목록·지표 — channel-detail-view의 콘텐츠 목록은 이 스펙에서 다루지 않는다. 네이버 블로그 글 목록·글별 조회수를 가져오는 것은 별도로 결정할 사항이다.

## Further Notes

- 이 수집기는 네이버가 공식적으로 지원하지 않는 방식(비공식 자동 로그인)에 기대고 있다는 점을 항상 전제해야 한다. PRD의 "4개 채널 완전 무중단 자동 수집 보장은 범위 밖"이 바로 이 수집기를 가리킨다.
- 로그인 ID·비밀번호·저장된 세션 파일은 metrics-store 스펙의 "자동 수집 연동에 필요한 비밀 정보는 설정 값으로 분리" 원칙을 그대로 따른다.
- 세션 재사용 방식은 youtube-collector의 OAuth 리프레시 토큰 재사용과 목적은 같지만(매번 재인증하지 않기) 메커니즘은 다르다 — OAuth는 토큰 발급/갱신이 네이버의 로그인 자동화보다 공식적이고 안정적이다. 두 수집기를 같은 패턴으로 다루려 하지 않는다.
