# Spec — youtube-collector

## Status: 시청시간(OAuth) 범위 축소됨

구독자수·조회수(API 키 방식)는 구현되어 실제로 동작 중이다. 시청시간(OAuth + YouTube Analytics API)은 실제로 연결까지는 성공했으나, Analytics API 리포트 호출이 계속 400 오류를 반환해 담당자와 상의 후 포기했다 (2026-10-15). 과거 월 데이터를 Analytics API로 복원하려던 backfill 기능도 같은 이유로 함께 제거했다. 관련 코드(`lib/oauth.ts`, `lib/youtubeOAuth.ts`, `lib/youtubeAnalytics.ts`, `lib/youtubeBackfill.ts`, `/api/auth/youtube/*`, `/api/collectors/youtube/backfill`)는 삭제했고, `시청시간`은 더 이상 지표 목록에 없다. 아래 시청시간 관련 내용은 추후 재시도 시 참고용으로만 남겨둔다.

## Problem Statement

담당자가 매달 유튜브 채널 관리자 페이지에 로그인해 구독자수·조회수·시청시간을 눈으로 확인하고 엑셀에 옮겨 적는다. 이 세 지표는 담당자가 직접 보지 않아도 매번 같은 방식으로 확인할 수 있는 숫자인데도, 로그인·클릭·기록을 매달 반복한다.

## Solution

유튜브 구독자수·조회수·시청시간을 자동으로 가져와 metrics-store에 채워 넣는다.

- **구독자수·조회수**는 API 키만으로 가져온다. 담당자의 로그인이 필요 없다.
- **시청시간**은 API 키로는 가져올 수 없고, 채널 소유 구글 계정의 1회 로그인 허용(OAuth 연결)이 있어야 가져올 수 있다. 연결은 한 번만 하면 되고, 이후에는 자동으로 유지된다.
- 담당자는 화면에서 "API 키 연결 상태"와 "시청시간 연결(OAuth) 상태"를 각각 확인하고, 연결이 끊기면 다시 연결할 수 있다.
- 담당자는 화면에서 지금 바로 유튜브 수집을 실행해볼 수 있다. (주기적인 자동 실행 스케줄은 collection-scheduler의 범위)
- 수집한 값은 metrics-store에 `source: auto`로 저장되며, 담당자가 manual-metrics-entry에서 이미 손으로 고친 값이 있으면 그 값을 덮어쓰지 않는다 (metrics-store의 보호 규칙을 그대로 따른다).

## User Stories

1. As a 담당자, I want 유튜브 구독자수·조회수가 매번 자동으로 채워지길, so that 매달 로그인해서 눈으로 확인하지 않아도 된다.
2. As a 담당자, I want 유튜브 시청시간도 자동으로 채워지길, so that 세 지표를 전부 수동으로 옮겨 적지 않아도 된다.
3. As a 담당자, I want 시청시간을 가져오려면 채널 소유 계정으로 한 번만 로그인하면 되길, so that 매달 다시 로그인하지 않아도 된다.
4. As a 담당자, I want 화면에서 API 키가 연결되어 있는지, 시청시간 연결(OAuth)이 살아있는지 구분해서 보고 싶다, so that 어느 쪽이 문제인지 바로 안다.
5. As a 담당자, I want 시청시간 연결이 끊기거나 만료되면 화면에서 바로 알 수 있길, so that 다음 달 보고서에 숫자가 비는 것을 미리 막을 수 있다.
6. As a 담당자, I want 연결이 끊긴 시청시간 연결을 화면에서 버튼 하나로 다시 연결할 수 있길, so that 개발자를 부르지 않아도 스스로 복구할 수 있다.
7. As a 담당자, I want 지금 당장 유튜브 수집을 눌러서 실행해볼 수 있길, so that 정기 수집을 기다리지 않고 바로 숫자를 채울 수 있다.
8. As a 담당자, I want 자동 수집이 실패해도 대시보드가 비어 보이지 않고, manual-metrics-entry로 그 달 숫자를 직접 채울 수 있길, so that 보고서 작성이 막히지 않는다.
9. As a 담당자, I want 이미 손으로 고친 유튜브 지표 값이 자동 수집으로 다시 덮어써지지 않길, so that 어렵게 고친 값이 되돌아가지 않는다.
10. As a 개발자, I want API 키·OAuth 클라이언트 정보·리프레시 토큰이 코드에 들어가지 않고 설정 값으로 분리되길, so that 비밀 정보가 저장소에 노출되지 않는다.
11. As a 담당자, I want 수집된 값이 그 즉시 채널 대시보드에 반영되길, so that 수집 결과를 바로 확인할 수 있다.

## Implementation Decisions

**수집 대상과 방식**

| 지표 | API | 인증 방식 | 성격 |
|---|---|---|---|
| 구독자수 (subscribers) | YouTube Data API v3 `channels.list` (`part=statistics`) | API 키만 | 조회 시점의 누적 값 (스냅샷) |
| 조회수 (views) | YouTube Data API v3 `channels.list` (`part=statistics`) | API 키만 | 조회 시점의 누적 값 (스냅샷) |
| 시청시간 (watch_time) | YouTube Analytics API `reports.query` (`estimatedMinutesWatched`, 날짜 범위 = 해당 연월 1일~말일) | OAuth2 사용자 인증 (채널 소유 계정, `yt-analytics.readonly` 스코프) | **그 달 한 달 동안** 발생한 값 (기간 합계) — 구독자수·조회수와 성격이 다름 |

- 구독자수·조회수는 "그 순간의 누적 총량"을 그 달의 값으로 저장한다. metrics-store의 증감 계산(이번 달 스냅샷 − 지난달 스냅샷)이 그대로 "한 달 동안 늘어난 양"이 된다 — 담당자가 지금까지 확인해온 방식과 동일하다.
- 시청시간은 애초에 "그 달 동안의 합계"를 가져오므로, 저장되는 값 자체가 이미 그 달의 양이다.

**연결(인증) 관리**

- API 키·채널 ID는 비밀 정보로 분리 보관한다 (코드에 넣지 않음). 구독자수·조회수 수집은 이 두 값만 있으면 바로 동작한다.
- 시청시간은 별도의 OAuth2 연결이 필요하다. 연결 상태를 `connected | disconnected | error`로 관리하고, 마지막 연결 성공 시각과 마지막 오류 메시지를 함께 보관한다.
- OAuth 연결 흐름: 담당자가 화면에서 "연결하기"를 누르면 구글 인증 화면으로 이동 → 채널 소유 계정으로 로그인·동의 → 돌아오는 콜백에서 리프레시 토큰을 발급받아 저장한다.
- 저장된 리프레시 토큰이 만료되거나 구글 쪾에서 거부하면, 연결 상태를 `error`로 표시하고 담당자가 다시 "연결하기"를 눌러 재연결할 수 있게 한다.
- 리프레시 토큰·OAuth 클라이언트 비밀 값도 코드에 넣지 않고 설정 값으로 분리 보관한다.

**화면**

- 유튜브 연동 상태를 보여주는 화면(또는 영역)에 다음을 표시한다:
  - API 키 연결 여부 (설정값 존재 여부로 판단)
  - 시청시간 OAuth 연결 상태 (`connected | disconnected | error`), 마지막 연결/오류 시각
  - "연결하기" / "다시 연결하기" 버튼 (OAuth 흐름 시작)
  - "지금 수집" 버튼 — 누르면 구독자수·조회수·(연결되어 있다면) 시청시간을 즉시 가져와 metrics-store에 저장하고, 결과(성공/부분 실패/실패)를 화면에 보여준다.
- 이 화면은 추후 collection-scheduler가 모든 채널의 연결 상태·수집 이력을 모아 보여주는 화면으로 확장될 수 있다. 지금은 유튜브 하나만 다룬다.

**metrics-store와의 연결**

- 수집한 각 값은 metrics-store의 upsert 규칙을 그대로 따른다: `channel: youtube`, `metricKey: subscribers | views | watch_time`, `yearMonth`, `value`, `source: auto`.
- 해당 (채널, 지표, 연월)에 이미 `is_manual_override`가 설정된 값이 있으면, 자동 수집 값은 저장되지 않고 건너뛴다 (metrics-store의 기존 규칙 그대로 재사용, 이 스펙에서 새로 만들지 않음).

**오류 처리**

- 구독자수·조회수 수집이 실패하면(API 키 오류, 네트워크 오류 등) 해당 월의 값은 비워두고, 담당자가 manual-metrics-entry로 채울 수 있도록 둔다. 재시도는 하지 않는다 (재시도·스케줄링은 collection-scheduler의 범위).
- 시청시간 수집은 연결이 없거나 오류 상태면 처음부터 시도하지 않고 건너뛴다.

## Out of Scope

- 정기적으로(예: 매일 1회) 자동 실행되는 스케줄링, 전체 채널 공통의 마지막 수집 시각·성공/실패 기록 화면 — collection-scheduler의 범위.
- 구독자수·조회수·시청시간 외의 다른 유튜브 지표(좋아요, 댓글 수 등) — PRD에 없는 지표는 다루지 않는다.
- 여러 유튜브 채널 동시 관리 — 유진그룹의 단일 채널만 대상으로 한다.
- 시청시간 OAuth 연결이 끊겼을 때 자동으로 알림(이메일·슬랙 등)을 보내는 기능 — 화면에 상태만 표시한다.

## Further Notes

- 구독자수·조회수(스냅샷)와 시청시간(기간 합계)은 저장 방식과 API 인증 방식이 서로 다르다는 점을 구현할 때 혼동하지 않아야 한다. 하나의 "유튜브 수집"처럼 보이지만 내부적으로는 서로 다른 두 개의 수집 경로다.
- API 키·OAuth 클라이언트 ID/Secret·리프레시 토큰은 metrics-store 스펙의 "자동 수집 연동에 필요한 비밀 정보는 설정 값으로 분리" 원칙을 그대로 따른다.
- 채널 ID(유진그룹 유튜브 채널)도 코드에 하드코딩하지 않고 설정 값으로 둔다.
