# PRD — 유진그룹 대내외 커뮤니케이션 채널 운영 지표 대시보드

## Problem Statement

홍보팀 대내외 커뮤니케이션 채널 운영 담당자는 매달 유진에버·유튜브·인스타그램·네이버 블로그 4개 채널의 주요 지표를 모아 전월 대비 증감을 정리하고 팀장·윗선에 공유한다.

이 작업이 번거로운 이유:

- 매달 4개 채널 관리자 페이지에 일일이 로그인해서 숫자를 눈으로 확인해야 한다.
- 확인한 숫자를 엑셀에 옮겨 적는 것이 제일 손이 많이 간다.
- 엑셀에서 이번 달과 지난달을 나란히 놓고 증감을 계산한 뒤, 다시 보고서 양식에 옮겨 채워야 한다.

이 월 단위 반복 작업을, 화면만 열면 4개 채널 지표와 전월 대비 증감이 바로 보이는 실시간 대시보드로 바꾸려 한다.

## Solution

홍보팀 채널 운영 담당자와 팀장·윗선을 위한 **채널 운영 지표 대시보드**.

- 화면을 열면 유진에버·유튜브·인스타그램·네이버 블로그 4개 채널의 주요 지표와 전월 대비 증감(▲▼, 증감폭·증감률)이 한눈에 보인다.
- 각 채널 지표는 자동 수집으로 채워지는 것을 원칙으로 한다. 유튜브·인스타그램은 각 채널이 제공하는 연동으로, 네이버 블로그는 저장된 로그인 정보로 관리자 통계 화면을 읽어와서, 유진에버는 사내 데이터베이스에서 직접 가져온다.
- 자동 수집이 실패하거나 아직 연결되지 않은 채널은, 담당자가 그 채널 관리자 화면에서 본 숫자를 대시보드에 직접 입력·수정할 수 있다. 대시보드가 빈 채로 멈추는 일은 없다.
- 팀장·윗선은 같은 화면을 열거나, 특정 월의 지표·증감을 정리한 요약 화면을 보고 공유받는다.

채널별 주요 지표:

| 채널 | 주요 지표 |
|---|---|
| 유진에버 | 방문자수, 조회수 |
| 유튜브 | 구독자수, 조회수, 시청시간 |
| 인스타그램 | 팔로워, 도달수, 저장수 |
| 네이버 블로그 | 조회수, 방문자수 |

## Features

1. **metrics-store** — 채널별·월별 주요 지표를 저장하고, 이번 달 숫자를 지난달과 나란히 놓아 전월 대비 증감(증감폭·증감률)을 계산한다. 지난달 데이터가 없거나 값이 비어 있는 경우의 처리 규칙을 포함한다. 다른 모든 기능이 이 저장소를 공유한다.

2. **channel-dashboard** — 화면을 열면 4개 채널의 주요 지표와 전월 대비 증감이 채널별 카드로 한눈에 보이는 메인 화면. 각 지표에 이번 달 값, 지난달 값, 증감폭, 증감률, 증가/감소 표시가 함께 나온다. 어느 채널이 언제 마지막으로 수집됐는지, 자동인지 수동인지도 표시한다.

3. **manual-metrics-entry** — 담당자가 특정 월·특정 채널의 지표 숫자를 직접 입력하거나, 자동 수집된 값을 고칠 수 있는 입력 화면. 자동 수집이 안 되는 채널·실패한 채널을 담당자가 손으로 채우는 통로이며, 손으로 고친 값은 다음 자동 수집이 덮어쓰지 않도록 표시된다.

4. **youtube-collector** — 유튜브 구독자수·조회수·시청시간을 자동으로 가져온다. 구독자수·조회수는 API 키로, 시청시간은 채널 소유 계정의 1회 연결(로그인 허용)로 수집한다. 담당자가 화면에서 연결 상태를 확인하고 연결·재연결할 수 있다.

5. **instagram-collector** — 인스타그램 팔로워·도달수·저장수를 자동으로 가져온다. 비즈니스 계정 연동으로 수집하며, 만료되는 접근 권한을 자동으로 갱신한다. 담당자가 화면에서 연결 상태를 확인하고 연결·재연결할 수 있다.

6. **naver-blog-collector** — 네이버 블로그 조회수·방문자수를, 저장된 로그인 정보로 관리자 통계 화면에 접속해 읽어온다. 네이버가 로그인을 다시 요구하거나 화면을 바꿔 수집이 멈추면, 담당자가 알 수 있도록 상태를 표시하고 manual-metrics-entry로 안내한다.

7. **online-sabo-collector** — 유진에버 방문자수·조회수를 사내 데이터베이스에서 직접 읽어온다. 접속 정보(데이터베이스 종류·주소·읽기 전용 계정·지표 위치)가 확인되기 전까지는 연결 설정만 비워둔 상태로 두고, manual-metrics-entry로 채운다.

8. **collection-scheduler** — 자동 수집을 정해진 주기(예: 매일)로 4개 채널에 대해 실행하고, 채널별로 마지막 수집 시각과 성공/실패 결과를 기록한다. 담당자가 화면에서 지금 즉시 수집을 다시 실행할 수도 있다.

9. **monthly-summary-view** — 특정 월을 골라, 그 달의 4개 채널 지표와 전월 대비 증감을 보고서 형태로 정리해 보여주는 화면. 팀장·윗선에게 링크로 공유하거나 화면을 그대로 캡처·인쇄해 공유할 수 있다.

10. **metrics-trend-chart** — 채널별 주요 지표의 최근 몇 달 추이를 꺾은선 그래프로 보여준다. (nice-to-have)

11. **channel-detail-view** — 채널별로 요약 화면(channel-dashboard)보다 자세히 볼 수 있는 화면. 그 채널의 이번 달 지표, 지표별 최근 추이(metrics-trend-chart), 그리고 그 채널에 어떤 콘텐츠(영상·게시물)가 올라갔는지와 콘텐츠 자체의 지표(조회수·좋아요·댓글 등)를 추이 분석 없이 목록으로 보여준다. 콘텐츠 목록은 해당 채널의 자동 수집 연동이 있어야 가능하다 (현재는 youtube-collector만 해당).

## Scope & Priorities

**핵심 (먼저 만들면 바로 쓸 수 있음)**

1. metrics-store
2. channel-dashboard
3. manual-metrics-entry

이 셋만 있어도 "엑셀에 옮겨 적고 증감 계산하고 보고서에 옮기는" 3단계가 "대시보드에 숫자 입력 1단계"로 줄어든다.

**핵심 (자동 수집)**

4. collection-scheduler (수집을 담아 돌리는 틀)
5. youtube-collector
6. naver-blog-collector
7. instagram-collector
8. online-sabo-collector (사내 DB 접속 정보 확인 후)

연결이 쉬운 순서로 붙인다. 유튜브가 가장 간단하고, 인스타그램은 연동 준비가 가장 번거롭고, 유진에버는 사내 정보 확인이 선행되어야 한다.

> **업데이트 (2026-10-10)**: naver-blog-collector는 실제로 시도해본 결과 네이버의 로그인 보안 확인(캡차)에 막혀 보류되었다. 네이버 블로그는 당분간 manual-metrics-entry로 수동 입력한다. (자세한 내용은 `docs/specs/naver-blog-collector.md` 참고)

**부가 (여유 있을 때)**

9. monthly-summary-view
10. metrics-trend-chart

## Out of Scope

- **채널 숫자가 튀거나 떨어진 원인 분석** — "왜 숫자가 올랐는지/떨어졌는지"를 콘텐츠 단위로 깊게 파고드는 분석은 하지 않는다. (수정: 각 채널에 어떤 콘텐츠가 올라갔는지와 그 콘텐츠 자체의 지표(조회수·좋아요·댓글 등)를 추이 없이 목록으로 보여주는 것까지는 범위에 포함한다 — channel-detail-view 참고. 원인을 추적하는 분석 기능만 범위 밖이다.)
- **4개 채널 완전 무중단 자동 수집 보장** — 네이버 블로그는 공식 통계 API가 없어 관리자 화면을 읽어오는 방식뿐이며, 네이버의 화면 변경·로그인 재요구 시 일시적으로 멈출 수 있다. 그래서 모든 채널에 수동 입력 통로(manual-metrics-entry)를 둔다.
- **지표 이외의 채널 관리 기능** — 콘텐츠 발행, 댓글 관리, 예약 등은 다루지 않는다. 이 도구는 지표 취합·증감·공유만 한다.
- **별도 로그인·권한 관리** — 사내망에서 접근하는 내부 도구로 전제한다. 담당자·팀장이 같은 화면을 본다. 계정별 접근 제어가 필요하면 별도 기능으로 추가한다.

## Further Notes

- **용어는 담당자의 말 그대로 쓴다.** 유진에버, 도달수, 저장수, 시청시간, 증감 비교 — 대시보드 화면과 문서에서 이 단어를 그대로 사용한다.
- **"실시간"의 의미** — 초 단위 갱신이 아니라, "매달 만드는 보고서" 대신 "언제 열어도 최신 달 숫자와 증감이 보이는 화면"을 뜻한다. 수집 주기는 하루 단위로 충분하다.
- **지표의 시간 단위는 '월'이다.** 모든 지표는 특정 연·월에 귀속되며, 증감은 항상 직전 월과 비교한다.
- **자동 수집 연동에 필요한 비밀 정보**(API 키, 접근 토큰, 네이버 로그인 정보, 사내 DB 계정)는 코드에 넣지 않고 설정 값으로 분리해 보관한다.
- **AI 기능은 현재 계획에 없다.** 필요 시(예: 증감에 대한 코멘트 자동 작성) 나중에 추가한다.
- 완성 예시는 `sample` 브랜치 참고.
